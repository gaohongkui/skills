公开的 agent skills 集合，按 [Agent Skills](https://agentskills.io/specification) 开放规范编写。
每个 skill 只有一份真身，所有目录、索引和 marketplace 清单都由脚本生成，不会走样。

正文全部用中文写；每个 `description` 末尾附一句英文触发句，让英文 agent 和 skills.sh 目录也能匹配到。

任何能读 `SKILL.md` 的客户端都能直接用：Claude Code、Codex、Copilot、Cursor、Gemini CLI、
DSH，以及 skills CLI 支持的 75+ 个目标。

## 安装

```bash
npx skills add gaohongkui/skills          # 装全部，自动识别已安装的客户端
npx skills add gaohongkui/skills --list   # 只看有哪些，不安装
```

单独装某一个，把地址指到它的目录即可：

```bash
npx skills add https://github.com/gaohongkui/skills/tree/main/skills/handoff-writer
```

skill 会落在 `.agents/skills/`（项目级）或 `~/.agents/skills/`（全局），再由 CLI 链接进各客户端
自己的目录。使用方不需要 clone，也不需要构建。

不想敲命令的话，把这句话直接丢给你的 agent，装和用一次完成：

```text
帮我安装 gaohongkui/skills 里的 skill-rsi，然后用它改造我的 <你的 skill 路径>
```

## 这个仓库是怎么长出来的

```text
skills/<name>/SKILL.md      ← skill 只在这一个地方写
├── scripts/                可选：可执行脚本
├── references/             可选：长文档，按需加载
├── assets/                 可选：模板与素材
└── evals/                  可选：触发与产出评测
        │
        │  npm run build
        ▼
index/skills.json · index/llms.txt · README 表格 · .claude-plugin/marketplace.json
```

生成的产物都带 GENERATED 头，CI 用 `npm run check` 校验 —— 目录过期会让构建失败，而不是悄悄
误导读者。README 表格由同一份数据**同时**生成到两个语言版本，所以中英两边不会各说各话。

## 推送前：隐私与敏感信息检查

**这个仓库是公开的，一次 push 不是草稿。** GitHub、skills CLI、skills.sh 都会快照并镜像
`SKILL.md`；公开仓库在首次推送后几分钟内就会被抓取。事后再删 commit，也收不回来。

每个 skill、每次推送 —— 先读
[`docs/publishing-checklist.md`](./docs/publishing-checklist.md)，然后跑：

```bash
npm run privacy              # 扫密钥、个人信息、内网主机、机器路径
npm run ci                   # 校验 + 生成文件一致性 + 隐私
git diff --cached            # 逐行读 —— 扫描器判断不了上下文
```

之所以做成闸门：skill 文件会被带到仓库之外的地方 —— 聊天窗口、别的 agent 的上下文、issue、
第三方目录。

| 检查项 | 不能进仓库的内容 |
| --- | --- |
| **个人信息** | 版权署名之外的真实姓名、家庭住址、私人邮箱/手机号/身份证、同事与客户姓名、聊天截图、日历或工单导出 |
| **密钥与凭据** | API key、token、密码、私钥、`.env`、Cookie、签名 URL、带密码的连接串 |
| **内部信息** | 内网主机名与 wiki 链接、项目代号、未发布路线图、非公开指标、IM 导出 |
| **机器指纹** | 家目录绝对路径（`/Users/<name>/…`）、内网 IP、主机名、设备 ID、shell 历史 |
| **第三方内容** | 你无权再分发的代码、文档、图片或数据 |

如果已经漏了：**先轮换凭据**，再用 `git filter-repo` 清历史并强推。如果已经公开，就把这个密钥
当成已泄露 —— 改写历史只是把字节从你的远端删掉，镜像、fork、缓存里还在。完整流程见
[清单](./docs/publishing-checklist.md#if-something-sensitive-already-slipped-through)。

## 贡献

先读 [`docs/adding-a-skill.md`](./docs/adding-a-skill.md)。最少是这三步：

```bash
mkdir -p skills/my-skill && $EDITOR skills/my-skill/SKILL.md
npm run build && npm run ci
```

真正要紧的规则：frontmatter 只写六个字段、`description` 必须写清**什么时候用**、
`SKILL.md` 控制在 300 行以内、以及上面那道隐私闸门要通过。`docs/` 下的文档目前是英文，
新增 skill 时不必翻译。
